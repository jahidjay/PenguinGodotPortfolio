## Reconciled

1. **D1 versus A1 — same file, two different rules, one coherent edit.** D1 targets **Rule 5** (what makes a run ranked) and A1 targets **Rule 30** (what `reset_settings()` keeps). They do not overlap in text, so they were applied as two edits in one pass rather than twice over the same sentence, and the header carries a single revision note naming both. The supporting edits each item implies were done once: D1's half reaches the "Run submit" call order and a new **AC-03a**; A1's half reaches **AC-26**. No wording was applied twice and no sentence was edited by both.
2. **A5 versus brief decision 3 — the Alarm Red half.** A5 asked for "a glyph/words rule" for Alarm Red text. Batch 1 had already gone **further** on the UX layer (style guide 3.1 rule 3: Alarm Red is never a text fill at all). Applying A5 literally would have re-introduced the weaker "red text with words" permission, so A5 was applied **at the level it was missing** — `design/art/art-bible.md` 7.10, which had no such rule — in the **stricter** form, and `design/ux/settings.md` (which still read "never used alone") was tightened to match. **No new colour was invented**; the lighter-red token stays an art-director decision in art bible 7.10 and style-guide Open Question 2.
3. **A5's two separate asks.** A5 bundles an input rule (group jump versus shoulder bindings), a document-status fix (`design/accessibility-requirements.md` 5.2 / G4) and the Alarm Red rule. They were applied to their three real owners — Accessibility Rule 21a, Input Rule 24c, the requirements file, and the art bible — with one shared wording for the group-jump rule so Accessibility and Input cannot drift. Both of A5's offered answers (a dedicated `nav_group_prev/next` verb pair, or the suppression rule) are recorded as acceptable, with suppression as the binding fallback, because picking one is Input's call and the UX requirement is satisfied either way.
4. **D13 was already half-done.** `design/ux/high-scores.md` had closed its own Open Question 1 in its post-review status line before batch 2 started. Only the question entry itself still read as open, so it was marked CLOSED with a pointer to the applied Menus Rule 40 text; nothing was changed twice.
5. **D15 went further than the item asked.** D15 said CB's "AC and debug values must be brought to 180 or the supersession removed". CB Rule 26 already declared the retirement, so the supersession was kept and **five further places** that still used the retired knob (F5 formula, F5 variable table, F5 example, tuning table, defaults list) were brought with it. AC-44 was turned from "`cb_banner_wait_max` <= 240" into "no `cb_banner_wait_max` key is present", which is the only form that keeps the data file honest.

## Open questions raised

1. **DONE / SKIPPED stamp rect (HUD GDD owner + Tutorial).** Left open, per brief decision 4. HUD GDD Rule 30b still places the stamps "in its column" with no rect in any `HudLayout`, so the layout lint (AC-03) cannot check them and the compact 48 px column form may not have room. Tracked as `design/ux/hud.md` Open Question 21 (raised in batch 1). **No rect invented.**
2. **Lighter Alarm Red text token (art-director).** Unchanged from batch 1 and now also recorded in `design/art/art-bible.md` 7.10: `#E03A3E` on Cabinet Char measures 3.95:1, so it is barred as a text fill everywhere. Whether to author a lighter token that reaches 4.5:1 is an art-bible palette decision. **No hex invented.** Style-guide Open Question 2.
3. **`nav_group_prev` / `nav_group_next` (Input).** Accessibility Rule 21a and Input Rule 24c both accept **either** a dedicated menu verb pair **or** the suppression rule, with suppression binding until a verb pair exists. Whether to add the verbs is Input's call. This is a deliberate either/or, not a gap: the UX requirement (group jump is never the only path and never steals a Fire/Drone/Bomb shoulder) is satisfied by the fallback alone.
4. **Which events each Target kit publishes (Kits, narrowed Tutorial OQ 7).** The per-plane `required_mask` means a missing event no longer bricks `tutorial.complete`, but it still shortens the School list on Sentry or Breaker. Deciding which of `charge_last_hit` / `drone_ability_started` each Target kit publishes stays a Kits (29) question. The "author plane-specific drills instead" option is **withdrawn**.
5. **Two font-spike numbers (Localization F3).** The **D10 plate width** at 9 digits + 2 separators, and the **INDIAN-grouping case** (81 px at D12, 3 px over budget). INDIAN is off by default so the second only matters if `digit_grouping` is ever enabled. Recorded in F3, not guessed.
6. **`tutorial.complete` OR-over-planes looseness (accepted, recorded).** A Lancer pilot who happens to clear exactly the subset a Breaker could clear counts as complete. Written into F3 as an accepted trade-off rather than fixed with a per-plane save key. Flagged here in case the game-designer wants the stricter form later; it would need a new Save key and is not a correctness bug.
